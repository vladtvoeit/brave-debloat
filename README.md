# brave-debloat

[![verify](https://github.com/vladtvoeit/brave-debloat/actions/workflows/verify.yml/badge.svg)](https://github.com/vladtvoeit/brave-debloat/actions/workflows/verify.yml)

Strip the crypto, ads, AI and telemetry out of Brave Browser — and make it
stick across reboots and updates.

Brave is a good browser wrapped in a storefront. This turns off the storefront.
Shields and auto-updates are left alone.

[Русская версия](README.ru.md)

---

## Install

**macOS**

```bash
curl -fsSL https://raw.githubusercontent.com/vladtvoeit/brave-debloat/main/macos/brave-debloat.sh | bash
```

**Windows** — in PowerShell *as administrator*:

```powershell
irm https://raw.githubusercontent.com/vladtvoeit/brave-debloat/main/windows/brave-debloat.ps1 | iex
```

Restart Brave afterwards. On macOS there is one manual step — see
[The macOS catch](#the-macos-catch) below.

## What gets disabled

| Group | Turned off |
|---|---|
| Crypto & money | Rewards / BAT, Wallet, web3 |
| Upsells | Brave VPN button and subscription prompts |
| AI | Leo — sidebar panel and omnibox suggestions; on-device local AI |
| Content features | News feed, Talk, Playlist, Speedreader, Wayback Machine |
| Networks | Tor windows, IPFS |
| Brave telemetry | P3A analytics, daily usage ping, Web Discovery |
| Chromium telemetry | Crash & usage reports, URL-keyed data collection, surveys |
| Nags | Promotional tabs, "make Brave default" prompts, background mode |
| Privacy Sandbox | Chromium's own ad-targeting stack — measurement, prompts, site-enabled ads |
| Network | Prefetch / prerender, spell-check service |

26 policies in total, plus a set of profile preferences for toolbar buttons
that have no policy equivalent.

**Not touched:** Shields, the ad blocker, auto-updates, sync, passwords,
your profile data.

**New tab backgrounds are left alone.** Brave's own photo wallpapers are not
ads, and nothing here touches them. Sponsored wallpapers — the ones that are
ads — can be disabled on request:

```bash
./brave-debloat.sh --sponsored          # macOS
.\brave-debloat.ps1 -Sponsored          # Windows
```

## How it works

Settings are applied in two layers, because neither one covers everything.

**Layer 1 — enterprise policies.** Most features have a real policy switch
(`BraveRewardsDisabled`, `BraveVPNDisabled`, …). A policy is authoritative:
the feature is gone, not just hidden, and the setting is greyed out in
`brave://settings`.

- Windows: written to `HKLM:\SOFTWARE\Policies\BraveSoftware\Brave`.
- macOS: delivered by a configuration profile.

**Layer 2 — profile preferences.** A few things have no policy — mainly
toolbar button visibility. Those are patched directly in the profile's
`Preferences` and `Local State` files, with timestamped backups.

On macOS the script also writes the same policy values into the user
preference domain (`defaults write com.brave.Browser`). Treat this as a minor
extra, not a second route: values there load at *recommended* level, and
Brave's own policies refuse that level, so Rewards, Wallet, Leo and News stay
on without the configuration profile. Only upstream Chromium policies that
accept being recommended take effect this way.

## The macOS catch

The obvious way to apply policies on macOS is to drop a plist into
`/Library/Managed Preferences/`. **This does not survive.** That directory is
generated by macOS from installed configuration profiles. A file written there
by hand is treated as stray and deleted — typically at the next reboot, taking
every policy with it. Everything comes back and you run the script again.
Forever.

So the script generates a proper `.mobileconfig` and hands it to System
Settings instead. Once installed, macOS regenerates the policy file from it on
every boot, which is exactly the behaviour you want.

A ready-made copy of the profile lives at
[`macos/brave-debloat.mobileconfig`](macos/brave-debloat.mobileconfig) if you
would rather install it by hand than run the script — the script generates an
identical one, only with fresh UUIDs.

**macOS does not allow installing a configuration profile from the command
line**, so this one step is manual:

> System Settings opens → **Review** → **Install** → admin password

If no window appears, it is waiting under
**System Settings → General → Device Management → Downloaded Profile**.

### Full Disk Access

macOS protects browser profile directories. Without Full Disk Access, reading
`Local State` fails with `Operation not permitted` for *any* process — sudo
does not help, because the check is per-application, not per-user.

If the script reports no access, grant it under **System Settings → Privacy &
Security → Full Disk Access** to whichever app runs the script (Terminal,
iTerm, …), then re-run. Policies still apply without it; only the toolbar
buttons are affected.

## Verify

Open `brave://policy` — every policy should be listed with status **OK**. Hit
*Reload policies* if the list looks stale.

Then `brave://settings`: Rewards, Wallet, VPN and Leo should be gone entirely,
not merely switched off.

## Uninstall

```bash
./brave-debloat.sh --uninstall          # macOS
.\brave-debloat.ps1 -Uninstall          # Windows
```

On macOS the configuration profile is removed by hand:
**System Settings → General → Device Management → Brave Debloat → remove.**

Profile preferences are not reverted automatically — restore a backup from
next to `Preferences` / `Local State` if you want them back. Each run keeps
`*.bak-initial`, the state from before the very first run, plus the two most
recent copies; older ones are pruned, since `Preferences` runs to megabytes.

## Options

| Flag | Effect |
|---|---|
| `--sponsored` / `-Sponsored` | Also disable sponsored new-tab wallpapers |
| `--no-profile` (macOS) | Skip the configuration profile |
| `-UserOnly` (Windows) | Write policies to HKCU instead of HKLM, per-account rather than machine-wide; still needs admin |
| `--uninstall` / `-Uninstall` | Revert what the script set |

Passing a flag through the one-line install:

```bash
curl -fsSL https://raw.githubusercontent.com/vladtvoeit/brave-debloat/main/macos/brave-debloat.sh | bash -s -- --sponsored
```

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/vladtvoeit/brave-debloat/main/windows/brave-debloat.ps1))) -Sponsored
```

## Notes

- Brave is quit before patching — it rewrites its preference files on exit,
  and would overwrite the changes.
- Re-run after major Brave updates: new releases add new features, and
  occasionally new preference keys that default to on.
- Policy names follow Brave's published policy list. A policy your Brave
  version does not know is simply ignored — `brave://policy` flags it as
  *Unknown policy*, which is the quickest way to catch a typo. (`IPFSEnabled`
  is the real name; `BraveIPFSEnabled`, which circulates in other scripts,
  silently does nothing.)
- Brave 155 marks five of these as deprecated: `IPFSEnabled`,
  `PromotionalTabsEnabled` and the three `PrivacySandbox*` ones. They still
  apply, and they still matter on older builds, so they are kept.
- Brave will start reporting that it is "managed by your organization". That
  is expected — the organisation is you.
- Run from a script file, the Windows version requests elevation itself via
  UAC. Piped through `iex` it cannot, so start an administrator PowerShell
  first. `-UserOnly` is not a way around this — Windows restricts
  `HKCU\SOFTWARE\Policies` to administrators too.
