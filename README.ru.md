# brave-debloat

Убирает из Brave крипту, рекламу, ИИ и телеметрию — так, чтобы настройки
переживали перезагрузки и обновления.

Brave — хороший браузер, обёрнутый в витрину. Это выключает витрину.
Shields и автообновления не трогаются.

[English version](README.md)

---

## Установка

**macOS**

```bash
curl -fsSL https://raw.githubusercontent.com/vladtvoeit/brave-debloat/main/macos/brave-debloat.sh | bash
```

**Windows** — в PowerShell *от администратора*:

```powershell
irm https://raw.githubusercontent.com/vladtvoeit/brave-debloat/main/windows/brave-debloat.ps1 | iex
```

После установки перезапустите Brave. На macOS остаётся один ручной шаг —
см. [Особенность macOS](#особенность-macos).

## Что отключается

| Группа | Что выключено |
|---|---|
| Крипта и деньги | Rewards / BAT, Wallet, web3 |
| Апселлы | Кнопка Brave VPN и предложения подписки |
| ИИ | Leo — панель в сайдбаре и подсказки в адресной строке; локальный ИИ на устройстве |
| Контентные функции | Лента новостей, Talk, Playlist, Speedreader, Wayback Machine |
| Сети | Окна Tor, IPFS |
| Телеметрия Brave | Аналитика P3A, ежедневный usage-ping, Web Discovery |
| Телеметрия Chromium | Отчёты о сбоях и использовании, сбор данных по URL, опросы |
| Назойливость | Промо-вкладки, предложения сделать браузером по умолчанию, фоновый режим |
| Privacy Sandbox | Рекламный механизм самого Chromium — измерения, запросы, реклама от сайтов |
| Сеть | Prefetch / prerender, служба проверки орфографии |

Всего 27 политик плюс набор настроек профиля для кнопок на тулбаре,
у которых эквивалента среди политик нет.

**Не трогается:** Shields, блокировщик рекламы, автообновления, синхронизация,
пароли, данные профиля.

**Фоновые фото на новой вкладке не трогаются.** Штатные обои Brave рекламой
не являются, и скрипт их не отключает. Спонсорские обои — то есть рекламные —
можно убрать отдельно:

```bash
./brave-debloat.sh --sponsored          # macOS
.\brave-debloat.ps1 -Sponsored          # Windows
```

## Как это устроено

Настройки применяются в два слоя — ни один из них не покрывает всё.

**Слой 1 — корпоративные политики.** У большинства функций есть настоящий
переключатель-политика (`BraveRewardsDisabled`, `BraveVPNDisabled`, …).
Политика авторитетна: функция исчезает, а не прячется, и настройка
в `brave://settings` становится неактивной.

- Windows: пишется в `HKLM:\SOFTWARE\Policies\BraveSoftware\Brave`.
- macOS: доставляется профилем конфигурации.

**Слой 2 — настройки профиля.** У части вещей политики нет — в основном это
видимость кнопок на тулбаре. Они правятся прямо в файлах `Preferences` и
`Local State` профиля, с бэкапами по метке времени.

На macOS скрипт дополнительно пишет те же значения политик в пользовательский
домен настроек (`defaults write com.brave.Browser`). Это мелкое дополнение, а не
второй путь: оттуда значения читаются как рекомендательные, а политики Brave
такой уровень не принимают — без профиля конфигурации Rewards, Wallet, Leo и
News останутся включёнными. Работают так только политики Chromium, которые
рекомендательный уровень допускают.

## Особенность macOS

Очевидный способ применить политики на macOS — положить plist в
`/Library/Managed Preferences/`. **Так не работает.** Этот каталог генерирует
сама macOS из установленных профилей конфигурации. Записанный туда вручную
файл система считает посторонним и удаляет — обычно при следующей перезагрузке,
вместе со всеми политиками. Всё возвращается, и скрипт надо запускать заново.
И так бесконечно.

Поэтому скрипт генерирует нормальный `.mobileconfig` и отдаёт его System
Settings. После установки macOS сама воссоздаёт файл политик при каждой
загрузке — именно то поведение, которое нужно.

Готовая копия профиля лежит в
[`macos/brave-debloat.mobileconfig`](macos/brave-debloat.mobileconfig) — если
проще поставить руками, чем запускать скрипт. Скрипт генерирует такой же,
только со свежими UUID.

**macOS не разрешает устанавливать профиль конфигурации из командной строки**,
поэтому этот шаг ручной:

> Откроется System Settings → **Review** → **Install** → пароль администратора

Если окно не появилось, профиль ждёт в разделе
**System Settings → General → Device Management → Downloaded Profile**.

### Full Disk Access

macOS защищает каталоги профилей браузеров. Без Full Disk Access чтение
`Local State` падает с `Operation not permitted` у *любого* процесса — `sudo`
не помогает, потому что проверка идёт на уровне приложения, а не пользователя.

Если скрипт сообщил об отсутствии доступа, выдайте его в разделе
**System Settings → Privacy & Security → Full Disk Access** тому приложению,
из которого запускается скрипт (Terminal, iTerm, …), и запустите заново.
Политики применяются и без этого — затронуты будут только кнопки на тулбаре.

## Проверка

Откройте `brave://policy` — все политики должны быть в списке со статусом
**OK**. Если список выглядит устаревшим, нажмите *Reload policies*.

Затем `brave://settings`: Rewards, Wallet, VPN и Leo должны исчезнуть
полностью, а не просто оказаться выключенными.

## Удаление

```bash
./brave-debloat.sh --uninstall          # macOS
.\brave-debloat.ps1 -Uninstall          # Windows
```

На macOS профиль конфигурации удаляется вручную:
**System Settings → General → Device Management → Brave Debloat → удалить.**

Настройки профиля автоматически не откатываются — при необходимости верните
бэкап, лежащий рядом с `Preferences` / `Local State`. Каждый запуск сохраняет
`*.bak-initial` — состояние до самого первого прогона — и две последних копии,
а более старые удаляет: `Preferences` весит мегабайты.

## Ключи

| Ключ | Действие |
|---|---|
| `--sponsored` / `-Sponsored` | Отключить и спонсорские обои новой вкладки |
| `--no-profile` (macOS) | Пропустить профиль конфигурации |
| `-UserOnly` (Windows) | Политики в HKCU вместо HKLM — для учётной записи, а не для машины; права администратора всё равно нужны |
| `--uninstall` / `-Uninstall` | Откатить то, что сделал скрипт |

Передать ключ через однострочную установку:

```bash
curl -fsSL https://raw.githubusercontent.com/vladtvoeit/brave-debloat/main/macos/brave-debloat.sh | bash -s -- --sponsored
```

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/vladtvoeit/brave-debloat/main/windows/brave-debloat.ps1))) -Sponsored
```

## Примечания

- Перед правкой Brave завершается: при выходе он перезаписывает свои файлы
  настроек и затёр бы изменения.
- После крупных обновлений Brave скрипт стоит запустить заново: в новых
  версиях появляются новые функции, а иногда и новые ключи настроек, включённые
  по умолчанию.
- Имена политик взяты из опубликованного списка политик Brave. Политику,
  которой ваша версия Brave не знает, она просто игнорирует — `brave://policy`
  помечает её как *Неизвестное правило*, и это быстрый способ поймать опечатку.
  (Правильное имя — `IPFSEnabled`; гуляющий по другим скриптам
  `BraveIPFSEnabled` молча не делает ничего.)
- Brave 155 помечает пять политик как устаревшие: `IPFSEnabled`,
  `PromotionalTabsEnabled` и три `PrivacySandbox*`. Они по-прежнему
  применяются и нужны на старых сборках, поэтому оставлены.
- Brave начнёт писать, что он «управляется вашей организацией». Это ожидаемо —
  организация тут вы сами.
- Запущенный из файла, Windows-скрипт сам запрашивает повышение прав через
  UAC. Через `iex` это невозможно, поэтому откройте PowerShell от
  администратора заранее либо используйте `-UserOnly`.
