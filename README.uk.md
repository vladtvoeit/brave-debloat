# brave-debloat

[![verify](https://github.com/vladtvoeit/brave-debloat/actions/workflows/verify.yml/badge.svg)](https://github.com/vladtvoeit/brave-debloat/actions/workflows/verify.yml)

Прибирає з Brave крипту, рекламу, ШІ та телеметрію — так, щоб налаштування
переживали перезавантаження й оновлення.

Brave — добрий браузер, загорнутий у вітрину. Це вимикає вітрину.
Shields і автооновлення не чіпаються.

[English version](README.md) · [Русская версия](README.ru.md)

---

## Встановлення

**macOS**

```bash
curl -fsSL https://raw.githubusercontent.com/vladtvoeit/brave-debloat/main/macos/brave-debloat.sh | bash
```

**Windows** — у PowerShell *від адміністратора*:

```powershell
irm https://raw.githubusercontent.com/vladtvoeit/brave-debloat/main/windows/brave-debloat.ps1 | iex
```

Після встановлення перезапустіть Brave. На macOS лишається один ручний крок —
див. [Особливість macOS](#особливість-macos).

## Що вимикається

| Група | Що вимкнено |
|---|---|
| Крипта й гроші | Rewards / BAT, Wallet, web3 |
| Апсели | Кнопка Brave VPN і пропозиції підписки |
| ШІ | Leo — панель у бічній панелі й підказки в адресному рядку; локальний ШІ на пристрої |
| Контентні функції | Стрічка новин, Talk, Playlist, Speedreader, Wayback Machine |
| Мережі | Вікна Tor, IPFS |
| Телеметрія Brave | Аналітика P3A, щоденний usage-ping, Web Discovery |
| Телеметрія Chromium | Звіти про збої та використання, збір даних за URL, опитування |
| Нав'язливість | Промовкладки, пропозиції зробити браузером за замовчуванням, фоновий режим |
| Privacy Sandbox | Рекламний механізм самого Chromium — вимірювання, запити, реклама від сайтів |
| Мережа | Prefetch / prerender, служба перевірки орфографії |

Усього 26 політик плюс набір налаштувань профілю для кнопок на панелі
інструментів, які не мають відповідника серед політик.

**Не чіпається:** Shields, блокувальник реклами, автооновлення, синхронізація,
паролі, дані профілю.

**Фонові фото на новій вкладці не чіпаються.** Штатні шпалери Brave рекламою
не є, і скрипт їх не вимикає. Спонсорські шпалери — тобто рекламні — можна
прибрати окремо:

```bash
./brave-debloat.sh --sponsored          # macOS
.\brave-debloat.ps1 -Sponsored          # Windows
```

## Як це влаштовано

Налаштування застосовуються у два шари — жоден із них не покриває всього.

**Шар 1 — корпоративні політики.** Більшість функцій має справжній
перемикач-політику (`BraveRewardsDisabled`, `BraveVPNDisabled`, …).
Політика авторитетна: функція зникає, а не ховається, і налаштування
в `brave://settings` стає неактивним.

- Windows: записується в `HKLM:\SOFTWARE\Policies\BraveSoftware\Brave`.
- macOS: доставляється профілем конфігурації.

**Шар 2 — налаштування профілю.** Для частини речей політики немає — здебільшого
це видимість кнопок на панелі інструментів. Вони змінюються просто у файлах
`Preferences` і `Local State` профілю, з резервними копіями за часовою міткою.

На macOS скрипт додатково записує ті самі значення політик у користувацький
домен налаштувань (`defaults write com.brave.Browser`). Це дрібне доповнення, а
не другий шлях: звідти значення читаються як рекомендаційні, а політики Brave
такого рівня не приймають — без профілю конфігурації Rewards, Wallet, Leo і
News залишаться увімкненими. Так працюють лише політики Chromium, які
рекомендаційний рівень допускають.

## Особливість macOS

Очевидний спосіб застосувати політики на macOS — покласти plist у
`/Library/Managed Preferences/`. **Так не працює.** Цей каталог генерує сама
macOS зі встановлених профілів конфігурації. Записаний туди вручну файл система
вважає стороннім і видаляє — зазвичай під час наступного перезавантаження,
разом з усіма політиками. Усе повертається, і скрипт доводиться запускати
знову. І так без кінця.

Тому скрипт генерує нормальний `.mobileconfig` і передає його System Settings.
Після встановлення macOS сама відтворює файл політик під час кожного
завантаження — саме та поведінка, яка потрібна.

Готова копія профілю лежить у
[`macos/brave-debloat.mobileconfig`](macos/brave-debloat.mobileconfig) — якщо
простіше встановити вручну, ніж запускати скрипт. Скрипт генерує такий самий,
лише зі свіжими UUID.

**macOS не дозволяє встановлювати профіль конфігурації з командного рядка**,
тому цей крок ручний:

> Відкриється System Settings → **Review** → **Install** → пароль адміністратора

Якщо вікно не з'явилося, профіль чекає в розділі
**System Settings → General → Device Management → Downloaded Profile**.

### Full Disk Access

macOS захищає каталоги профілів браузерів. Без Full Disk Access читання
`Local State` завершується помилкою `Operation not permitted` у *будь-якого*
процесу — `sudo` не допомагає, бо перевірка відбувається на рівні застосунку,
а не користувача.

Якщо скрипт повідомив про відсутність доступу, надайте його в розділі
**System Settings → Privacy & Security → Full Disk Access** тому застосунку,
з якого запускається скрипт (Terminal, iTerm, …), і запустіть знову.
Політики застосовуються й без цього — зачеплені будуть лише кнопки на панелі
інструментів.

## Перевірка

Відкрийте `brave://policy` — усі політики мають бути в списку зі статусом
**OK**. Якщо список виглядає застарілим, натисніть *Reload policies*.

Потім `brave://settings`: Rewards, Wallet, VPN і Leo мають зникнути
повністю, а не просто бути вимкненими.

## Видалення

```bash
./brave-debloat.sh --uninstall          # macOS
.\brave-debloat.ps1 -Uninstall          # Windows
```

На macOS профіль конфігурації видаляється вручну:
**System Settings → General → Device Management → Brave Debloat → видалити.**

Налаштування профілю автоматично не відкочуються — за потреби поверніть
резервну копію, що лежить поруч із `Preferences` / `Local State`. Кожен запуск
зберігає `*.bak-initial` — стан до найпершого прогону — і дві останні копії,
а старіші видаляє: `Preferences` важить мегабайти.

## Ключі

| Ключ | Дія |
|---|---|
| `--sponsored` / `-Sponsored` | Вимкнути й спонсорські шпалери нової вкладки |
| `--no-profile` (macOS) | Пропустити профіль конфігурації |
| `-UserOnly` (Windows) | Політики в HKCU замість HKLM — для облікового запису, а не для машини; права адміністратора все одно потрібні |
| `--uninstall` / `-Uninstall` | Відкотити те, що зробив скрипт |

Передати ключ через однорядкове встановлення:

```bash
curl -fsSL https://raw.githubusercontent.com/vladtvoeit/brave-debloat/main/macos/brave-debloat.sh | bash -s -- --sponsored
```

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/vladtvoeit/brave-debloat/main/windows/brave-debloat.ps1))) -Sponsored
```

## Примітки

- Перед змінами Brave закривається: під час виходу він перезаписує свої файли
  налаштувань і затер би зміни.
- Після великих оновлень Brave скрипт варто запустити знову: у нових версіях
  з'являються нові функції, а іноді й нові ключі налаштувань, увімкнені за
  замовчуванням.
- Назви політик узято з опублікованого списку політик Brave. Політику, якої
  ваша версія Brave не знає, вона просто ігнорує — `brave://policy` позначає її
  як *Невідоме правило*, і це швидкий спосіб упіймати друкарську помилку.
  (Правильна назва — `IPFSEnabled`; `BraveIPFSEnabled`, що гуляє іншими
  скриптами, мовчки не робить нічого.)
- Brave 155 позначає п'ять політик як застарілі: `IPFSEnabled`,
  `PromotionalTabsEnabled` і три `PrivacySandbox*`. Вони досі застосовуються
  й потрібні на старіших збірках, тому залишені.
- Brave почне писати, що ним «керує ваша організація». Це очікувано —
  організація тут ви самі.
- Запущений із файлу, Windows-скрипт сам запитує підвищення прав через UAC.
  Через `iex` це неможливо, тому відкрийте PowerShell від адміністратора
  заздалегідь. `-UserOnly` обійти це не допоможе: гілку
  `HKCU\SOFTWARE\Policies` Windows теж закриває від звичайних користувачів.
